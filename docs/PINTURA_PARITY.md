# Pintura feature and experience parity ledger

Audit date: 2026-11-11. Baseline: `c73ec4f` (`2.0.0-rc.1`). Reference: the current public Pintura product, tour and version 8 documentation. This is a capability and quality comparison, not a plan to reproduce proprietary source code, assets, filter coefficients or API names.

**Full parity has not been established.** The existing tests prove a useful local still-image editor, not the complete reference feature set. A similarly named button or matching preset count is not proof of equivalent behavior or visual quality. Changes in progress remain unverified until their acceptance evidence is recorded here.

## Status and proof rules

- **Verified:** the described behavior has a relevant automated or manual check in our implementation. This does not imply every advanced option in its family is supported.
- **Partial:** a useful implementation exists, but the row identifies an advanced capability, contract or quality gap.
- **Missing:** no equivalent supported implementation was found in the audited baseline.
- **Unverified:** source suggests support, or a quality claim needs evidence that existing tests do not provide.

Source and test paths below refer to this repository unless marked **host**. Tests are evidence for their actual assertions only. Chromium results do not establish Safari, Firefox, screen-reader, physical-touch, low-memory or slow-device support. The local reference screenshots in `.cache/pintura-reference` help compare control layout, but several reference canvases are blank because of headless WebGL limitations; they cannot prove pixel-level or complete visual parity.

## Optional extensions and host-owned capabilities

The host implements atomic per-version storage of original pixels, editable document and export settings; reopening loads the original before restoring the document. Its authenticated API checks prove original byte retention, state-only revisions, identical-save no-ops, concurrent-save conflicts, prior revision retention and flattened-file compatibility. Browser acceptance proves saved text remains editable after reload, Cancel preserves the saved document, and mobile saves retain the expected dimensions. AI sends `getBaseImage()` (photo with geometry/adjustments and visible redactions, no layers) and applies the result with `replaceBase`, so manual layers stay editable and the AI step is one undo entry. Save stores the AI result as the source with a document whose `imageMatrix` places it; the host e2e asserts this matrix, the saved source change and that every manual layer is saved. Visible version history/revert across saved versions remains a separate gap.
